# 2026-06-03

## Session : polish UX tableau électrique + alignement métier NFC

**Contexte** : retours métier successifs après usage de la démo livrée
hier. Objectif : faire converger la sortie batIA avec la pratique réelle
de l'artisan (devis facturable vs fourni par occupant, propagation des
modifications canvas, lisibilité du tableau).

### A. Devis facturable — élargissement du circuit-only

**Cause** : "Lave-vaisselle" apparaissait toujours dans le devis facturable
alors que batIA n'est pas fournisseur d'électroménager. Idem LL/SL/Chaudière.

**Fix** : ajout de `DISHWASHER`, `WASHING_MACHINE`, `DRYER`, `BOILER` à
`CIRCUIT_ONLY_EQUIPMENT_TYPES` ([src/planrec/nfc_rules.py:55-65](../../src/planrec/nfc_rules.py#L55-L65)).
Ils restent dans le tableau électrique (circuit dédié + disjoncteur + câble)
mais hors devis facturable.

### B. Détail circuits — pièces désormais assignées aux spé et sèche-serviettes

**Cause** : Four / Plaque / LV / LL / SL / Chaudière / Sèche-serviettes
affichaient `rooms_served=[]` dans le tableau parce que l'agrégation
collapsait sur un simple compteur global.

**Fix** : refacto de la signature interne — `spec_counts: dict[…, int]`
devient `rooms_by_type: dict[…, list[str]]`, et `n_towel_warmers: int`
devient `towel_warmer_rooms: list[str]`. Chaque circuit conserve une room
([src/planrec/nfc_tableau.py:169-300](../../src/planrec/nfc_tableau.py#L169-L300)).

### C. Auto-sync canvas → tableau électrique (suppression du bouton "Recalculer devis")

**Cause** : drag-out d'une pastille pièce mettait à jour le devis affiché
mais le tableau électrique gardait la pièce supprimée. Le bouton
"🔄 Recalculer devis" était quasi inutile (sync devis ↔ canvas
déjà live) mais l'auto-sync ne se propageait pas à `devis_global`.

**Décision** : Option C — sync `editor_key` sur chaque mutation pastille
+ rebuild `devis_global` sur place, **et** suppression du bouton Recalculer
(devenu redondant). Layout colonnes 4 → 3.

**Fix** : deux helpers `_sync_editor_key_from_pastilles()` +
`_rebuild_devis_global_from_editor()` dans `app/streamlit_app.py` ;
wiring dans les cascades `removed_pids` + `added_pastilles` + Phase 2/3
sync editor.

### D. Cascade Qté ↔ pastilles dans la box devis

**Cause** : modifier la Qté d'un équipement dans la box mettait à jour
le total devis mais pas le nombre de pastilles sur le canvas →
décrément buggy au prochain drag-out (Qté=2, _equip_ids=[3 ids], drag-out
1 pastille → Qté=1 au lieu de 2).

**Fix** : callback `_on_devis_edit` cas spécial `widget_suffix == "qty"`
appelant `reconcile_equipments_for_line()` pour synchroniser
`equipments_state` + `_equip_ids`. Caption obsolète "cliquer Générer devis
après modif Qté" supprimée.

### E. Cascade room pastille drag-out — équipements orphelins

**Bug 1** : après drag-out d'une chambre, devis filtré ✓ mais pastilles
équipements restaient sur le canvas. Cause : `_eq_just_populated` pas posé
dans la cascade room → la ligne 1756 écrasait `equipments_state` filtré
avec l'écho React stale au tour suivant.

**Fix 1** : ajout du flag dans la cascade `removed_pids`.

**Bug 2** : équipements ajoutés manuellement à la palette (`id="new_*"`)
restaient préservés inconditionnellement par le filtre React, même quand
Python les avait supprimés via cascade room. Devenaient orphelins.

**Fix 2** : filtre React useEffect élargi pour vérifier que la `room` du
`new_*` est encore dans `pastille_to_devis_room` (sinon drop), rebuild
`dist/` du composant
([PastilleCanvas.tsx:901-933](../../app/components/pastille_canvas/frontend/src/PastilleCanvas.tsx#L901-L933)).

### F. Préservation des labels pièces après suppression intermédiaire

**Cause** : après drag-out de "Chambre 2" sur un plan à 3 chambres,
`generate_tableau` ré-indexait via `cat_seen` → l'ex-"Chambre 3" devenait
"Chambre 2" dans le tableau, alors que sa pastille restait labellée
"Chambre 3". Confusion utilisateur.

**Fix** : ajout d'un paramètre optionnel `room_labels: dict[room_id → label]`
à `generate_tableau`. Si fourni, court-circuite `cat_seen`. Le rebuild
utilise désormais `pastille_id` comme `room_id`, et le call-site Streamlit
construit le map depuis `pastilles_state`.

### G. Homogénéisation labels RCD (SVG/PDF vs HTML)

**Cause** : SVG/PDF affichait `ID 63 A` (calibre préfixé "ID") tandis que
le détail HTML affichait `ID 1 Type A` (index séquentiel). Cross-référence
impossible.

**Fix** : tous les rendus utilisent maintenant `ID N` (index) en gras +
`{calibre} A · Type {X}` en sous-titre +`{sensibilité} mA`
([tableau_renderer.py:58-77](../../src/planrec/tableau_renderer.py#L58-L77) et [218-237](../../src/planrec/tableau_renderer.py#L218-L237)).

### H. Wrap label sur trait d'union

**Cause** : "Sèche-serviettes" (15 chars, sans espace) dépassait visuellement
le module SVG 60 px (overflow gracieux du wrap original = mot seul → dépasse).

**Fix** : `_wrap_label` découpe aussi sur `-` ("Sèche-serviettes" →
`["Sèche-", "serviettes"]`). 3 tests ajoutés.

### I. Alignement métier NFC — 3 corrections de règles

| Sujet | Avant | Après |
|---|---|---|
| **Séjour : prises** | `max(5, surface/4) + 3` (les 3 TV en sus) | `max(5, surface/4)` (3 TV incluses dans les 5 mini) |
| **Cuisine : prises** | `SOCKET = 6` | `SOCKET = 9` (6 normales + 3 alim spé Plaque/Four/LV) |
| **RCD min T1** | 1 | 2 (NFC §10.1G impose 2 minimum) |
| **RCD calibre cumulus** | `BOILER` traité × 0.5 | `BOILER` ajouté au set `heat_types` → plein pot (ECS = chauffage continu NFC) |

Refs : [nfc_rules.py:147-194](../../src/planrec/nfc_rules.py#L147-L194), [nfc_tableau.py:308-355](../../src/planrec/nfc_tableau.py#L308-L355).

### J. Discussion (non-implémenté) : NFC §701 volumes pièces humides

Ouvert l'alignement sur les 4 volumes (0/1/2/caché) autour douche/baignoire :
IPX requis, TBTS 12V, classe II, DDR 30 mA dédié. Aujourd'hui batIA a une
note SDB vague "⚠ Zone 60 cm". Court terme = enrichir la note explicite
sur les volumes ; moyen terme = validation spatiale des pastilles via
détection douche/baignoire ; long terme = DDR 30 mA SDB auto + classe II
éclairage en volume 2. **Reporté à session dédiée.**

### K. Discussion (non-implémenté) : répartition intelligente éclairage/prises

NFC C15-100 §771 + tableau 10-1G : éclairage et prises doivent être
répartis sur ≥ 2 DDR (éviter le black-out d'une zone si un circuit saute).
Aujourd'hui le bin-packing greedy peut concentrer toutes les pièces de vie
sur un même circuit. **Reporté à session dédiée.**

### L. Discussion (non-implémenté) : tie-break Type AC vs Type A

Constat : Lave-vaisselle finit sur RCD 1 Type A par effet de bord du
bin-packing (égalité de remplissage, tie-break index croissant). Aucune
exigence normative — c'est juste "sous-optimal" car gaspille un slot Type A
plus cher. Fix proposé : préférer Type AC sur tie-break pour les circuits
non requires_type_a. **Reporté à session dédiée.**
