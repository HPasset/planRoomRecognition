### Refactor UX du tableau Devis : groupement par pièce + toggle déplier/replier

**Contexte** : sur des devis avec beaucoup de pièces (logement T5+ par ex), le tableau devis peut afficher 30+ lignes d'équipements consécutifs, ce qui devient illisible. L'user veut pouvoir replier les équipements pièce par pièce pour ne voir que les noms de pièces, avec un toggle global pour tout ouvrir/fermer d'un coup. Le design du tableau (st.columns row-by-row) doit être conservé tel quel — il est apprécié visuellement.

**Mise en œuvre** dans `app/streamlit_app.py` (refactor du bloc de rendering du devis, après "➕ Ajouter une ligne") :

1. **Groupement par pièce** : avant le rendering, parcours du `df_devis` pour construire `pieces_in_order` (liste des pièces dans l'ordre d'apparition, sans doublons).

3. **Toggle global** : checkbox **"📂 Tout dérouler / 📁 Tout enrouler"** placée au-dessus des headers (pas dans la sidebar, comme demandé). Quand l'user la change, tous les `expanded[piece]` sont mis à la même valeur + `st.rerun()`.

### 🐛 Fix bug toggle global "Tout dérouler" + repositionnement sous-totaux

**Contexte** : suite au refactor précédent, 2 problèmes UX remontés par l'user :

1. **Bug fonctionnel** : "lorsque la case Tout dérouler est cochée alors je ne peux plus rentrer de pièce". Quand l'user cochait le toggle global, il ne pouvait plus replier une pièce individuellement via son chevron ▶/▼.

2. **Critique UX** : le sous-total `Σ XXX.XX` placé à droite (col 6 = Total TTC) du header pièce était mal placé. L'user veut le **sous le détail des équipements**, **aligné à gauche** avec la colonne Détail.

**Cause racine bug #1** : ma logique précédente comparait `new_all != all_expanded` à CHAQUE rerun. Quand l'user cliquait un chevron individuel pour replier une pièce :
- `expanded[Cuisine] = False`
- rerun
- `all_expanded` recomputé = False (Cuisine collapsed)
- État checkbox toujours True (l'user n'avait pas touché le toggle global)
- `True != False` → entre dans le `if` → re-force toutes les pièces à True → re-expand Cuisine
- Du coup le clic chevron de l'user est neutralisé instantanément

**Mise en œuvre fix #1** : passage au pattern `on_change` :
- Le callback `_on_global_toggle()` ne fire QUE quand l'user clique explicitement sur la checkbox
- Les autres reruns (chevrons individuels, ajout/suppression ligne) ne déclenchent PAS le callback → pas d'override
- Avant le render de la checkbox, force-sync de son état à l'état réel calculé : `st.session_state[toggle_key] = all_expanded_now`
- → Cohérence visuelle automatique : si l'user replie toutes les pièces une par une, le toggle global se décoche tout seul

```python
toggle_key = f"{devis_lines_key}_all_expand"
all_expanded_now = bool(pieces_in_order) and all(st.session_state[expanded_key].values())
st.session_state[toggle_key] = all_expanded_now  # force-sync AVANT le widget

def _on_global_toggle():
    new_val = bool(st.session_state[toggle_key])
    for p in pieces_in_order:
        st.session_state[expanded_key][p] = new_val

st.checkbox("📂 Tout dérouler / 📁 Tout enrouler", key=toggle_key, on_change=_on_global_toggle, ...)
```

**Mise en œuvre fix #2** : déplacement du sous-total :
- Retrait du `<b>Σ XXX.XX</b>` de la col 6 du header pièce (hcols[6] supprimé)
- Ajout d'une nouvelle row APRÈS les rows d'équipement, dans le bloc `if is_expanded:`
- Sous-total placé dans la col 2 (Équipement) → alignement gauche naturel (même alignement que les selectbox Équipement)
- Style : bleu marine batIA (#1f3a5f) en gras, format `Σ XXX.XX €`
- Visible seulement quand la pièce est déroulée (cohérent : pas de détail = pas de sous-total visible)

**Résultat** :
- ✅ Toggle global fonctionne correctement, ne bloque plus les interactions individuelles
- ✅ Sous-total bien aligné sous le détail, dans la colonne **Total TTC** (col 6) — initialement placé en col 2 Équipement par erreur d'interprétation, corrigé suite au feedback de l'user qui voulait l'alignement vertical avec les 180.00 / 60.00 / etc. de la même colonne
- ✅ Syntaxe OK + **38/38 tests AppTest** toujours OK
