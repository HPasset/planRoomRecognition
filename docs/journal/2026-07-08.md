# Journal — 2026-07-08

## Segmentation pièces : FR-only vs MSD→FR (séquentiel) — FR-only gagne

### Data
- 3 lots FR annotés CVAT (COCO 1.0) : Lot0 (107, ré-annoté formes simplifiées),
  Lot1 (82), Lot2 (86) = **275 plans**. 0 rectangle, 0 image vide.
- Conversion `cvat_to_panoptic.py` (chaque lot) + fusion union → dataset unique
  **`data/processed/fr_panoptic_v2`** (177/37/61, test gelé = union des tests).
- Classes rares maintenant couvertes (Garage ~122, Storage ~228).

### Expérience (2 bras, même dataset FR pur, même archi Swin-S, seule diff = init)
- **fr_only_v1** : init baseline COCO, LR 1e-5/1e-4.
- **stage_b_msd_v2** : init séquentiel depuis `stage_a_msd_v1/best.pt` (MSD, val
  MSD 0,753), LR bas 5e-6/5e-5. Séquentiel (pas de mix, pas d'oversample sources).
- Cloud : Modal A100 bf16, num_workers 8, wrapper `modal_train_fr_panoptic.py`
  (lance les 2 bras en parallèle). ~$3-4 total.

### Résultat — VERDICT : FR-only supérieur
- **Val mIoU** : fr_only **0,670** (ep 27) vs msd→fr **0,606** (ep 17, early-stop).
- **Test gelé (61 plans), mIoU hors Wall** : fr_only **0,661** vs msd→fr **0,585**
  (+0,076). fr_only gagne **8/9 classes** (msd n'égalise que Storage).
- Dynamique révélatrice : MSD→FR converge vite mais **plafonne bas** ; FR-only
  démarre lent et **monte plus haut**. Le pré-train MSD (plans vides sans mobilier)
  bride le plafond FR. **Même leçon que les murs : domain-match > volume hors-domaine.**
- Éval : `experiments/wall_detection_eval/` (script inline) — IoU par classe.

### Décisions
- **Modèle pièces = FR-only** (backbone COCO + FR). Abandon du pré-train MSD/CubiCasa
  pour les pièces → plus simple ET 100 % license-clean.
- **Prochaine annotation** : prioriser les classes faibles **Storage (0,36),
  Kitchen (0,45), Outdoor (0,57)**. fr_only overfit après ep 27 → plus de plans FR
  = plafond plus haut. L'annotation FR est LE levier.
- Règles mapping à garder constantes entre lots : Bureau→BedRoom, WC→Bath.

## Intégration app : deux modèles dédiés (pièces FR-only + murs DWG)

L'audit a confirmé que l'app tournait encore sur `stage_b_finetune_v1`
(CubiCasa+FR combiné, CC BY-NC + inférieur). **Corrigé.**

- Nouvelle classe `DualSegmentationInference` (`src/segmentation/inference.py`) :
  compose 2 `SegmentationInference` — pièces `fr_only_v1` (Swin-S, 768) +
  murs `wall_only_dwg_v3` (Swin-T, 640). Même contrat `.predict()->SegmentationOutput`,
  l'aval (fusion/OCR/NFC/snap-walls) ne voit aucune différence. Dégradation
  gracieuse si checkpoint mur absent (warning + murs du modèle pièces).
- App : `DEFAULT_CHECKPOINT`→`fr_only_v1`, `WALL_CHECKPOINT`→`wall_only_dwg_v3`,
  `load_seg_model()` construit le Dual. Clé de cache résultat corrigée
  (`best.pt` collisionnait entre runs → nom du run parent + tag mur).
- Smoke test (Plan_RDC2) : 8 pièces cohérentes, murs 25 366 px / 19 tracés,
  ~1,1 s MPS. 66 tests seg passent.
- **Bénéfice double** : qualité (fr_only bat le combiné) ET licence (100 %
  license-clean, plus de CubiCasa CC BY-NC dans le produit).
